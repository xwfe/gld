## 从 v0.8.2 升上来

换二进制、`gld daemon restart`。Client ID、授权口令、签名密钥、ChatGPT 注册的客户端都不动，连接器不用删、
不用重新授权。

- **ChatGPT 要点一次 Refresh**：`exec_command`、`check_command` 多了参数 `service_port`，`timeout_ms` 的上限和说明也改了。
  工具数没变。到 chatgpt.com/plugins 打开 gld 这条连接点 **Refresh**，再开新对话；不点照常能用，只是 AI 看不到新参数。
- **守护进程协议号没变（还是 5）**，但版本号变了：换完没重启时命令行报"守护进程版本不一致"（退出码 4），重启就好。
- **`gld daemon restart` 会让守护进程带上你这个终端的全部环境**。这一版起项目命令拿不到名字像密钥的变量（见下），但名字不像的、
  以及本机 MCP server 仍拿得到；在意的话交给 launchd / systemd 起，见[开机自启](https://github.com/xwfe/gld/blob/main/docs/daemon.md#开机自启)。

完整步骤、升级前后怎么比工具表指纹见[安装 · 升级](https://github.com/xwfe/gld/blob/main/docs/install.md#升级)。

## 这一版（0.8.3）的变化

- **dev server 用 `service_port` 起**：`exec_command` 带上服务要听的端口，端口上已经有东西在听就什么都不起（`PORT_IN_USE`，
  占着的是自己起的那条会给出它的 `session_id`）；端口在 127.0.0.1 或 ::1 上连得上才算起来，一连上就返回；能开到 1 小时
  （默认 30 分钟），普通命令仍是最多 10 分钟。回包的 `service` 说出它听在哪、同一网络的机器能不能访问；用 `kill_session`
  停掉时回包写 `service stopped`，不再写 `command FAILED`。ChatGPT 实测不用提示就会用。
  见[概念 · dev server 这类要一直开着的](https://github.com/xwfe/gld/blob/main/docs/concepts.md#dev-server-这类要一直开着的service_port)。
- **用浏览器验页面**（新文档，不是新代码）：经本机 MCP 转发一个单独配置的 Playwright MCP，AI 能打开服务模式起的页面、点、
  读 console 报错、截图。**别直接开你已经装的那个 `playwright`**：不写 `cwd` 的话它允许页面拿到你整个主目录下的文件；
  它还自带一个 `browser_run_code_unsafe`，能以你的身份跑任意代码，配置里要用 `disabled_tools` 关掉。
  配法见[概念 · 用浏览器验页面](https://github.com/xwfe/gld/blob/main/docs/concepts.md#用浏览器验页面单独配一个隔离的-playwright-mcp)。
- **装东西要你点头，扩到 JS 以外**：`pip install`（含 `python -m pip`）、uv、poetry、`cargo install` / `add` / `fetch`、
  `go install` / `get`、`npx` 跑项目里没装的包、`pnpm dlx`、`playwright install`（下几百 MB 浏览器）等，`exec_command` 不带
  `confirm=true` 不跑。`cargo build`、`go build`、`mvn install` 这类构建顺手下载依赖的不拦。
  完整清单见[概念 · 装东西的命令要你点头](https://github.com/xwfe/gld/blob/main/docs/concepts.md#装东西的命令要你点头)。
- **项目命令拿不到名字像密钥的环境变量**：守护进程从哪儿起就带着哪儿的环境，以前 AI 一句 `print(os.environ)` 就能读到你终端里的
  `GITHUB_TOKEN`、Claude Code 会话的令牌。现在名字以 TOKEN、SECRET、PASSWORD、API_KEY、AUTH 这类结尾的变量不交给项目命令，
  `check_exec_environment` 的 `withheld_environment` 列出扣下了哪些（只有名字）。命令本来就能以你的身份读文件，这一条只堵
  环境变量这条路。见[安全](https://github.com/xwfe/gld/blob/main/docs/security.md#项目命令拿不到名字像密钥的环境变量)。
- **`read_file` 找不到时说出项目里同名的文件**：ChatGPT 照浏览器 console 里的 `/app.js` 去读 `app.js` 时，报错里直接给出
  `public/app.js`（`details.same_name_elsewhere`），不用再列一次目录。
- `gld tool call` 的帮助更正：没有守护进程时，下一次调用照样读得到上一条命令的结局和输出（运行记录），只是进程已经停了。

## 可能影响你的行为变化

- 脚本或自动化经 `exec_command` 跑上面那些装东西的命令，要加 `confirm=true`，否则报 `DANGEROUS_OPERATION_REQUIRES_CONFIRMATION`。
- 项目里要密钥的测试（读 `OPENAI_API_KEY`、`NPM_TOKEN` 这类）经 gld 跑会读不到，要在你自己的终端里跑。名字看着不像密钥的
  （`DATABASE_URL` 里带口令）照旧挡不住。
- `timeout_ms` 在工具参数表里的上限写成了 3600000，但不带 `service_port` 时超过 600000 仍被拒（`POLICY_REJECTED`，原因
  `timeout_too_long`）。
- 工具数：compact 30、core 42、advanced 56、read-only 23，和 0.8.2 一样。

## 退回 0.8.2

换回旧二进制、`gld daemon restart` 即可，数据目录不用动。退回后 ChatGPT 若已刷新过工具表，再点一次 Refresh。

## 下载校验

每个包旁边有 `SHA256SUMS`：

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS    # Linux 上是 sha256sum -c --ignore-missing SHA256SUMS；只核你下了的包
```

核对包是这个仓库的发布流水线编的（要装 GitHub CLI）：

```bash
gh attestation verify gld-v0.8.3-aarch64-apple-darwin.tar.gz --repo xwfe/gld \
  --signer-workflow xwfe/gld/.github/workflows/release.yml
```

macOS 和 Windows 的包没有代码签名，第一次运行会被 Gatekeeper / SmartScreen 拦，处理办法见
[安装](https://github.com/xwfe/gld/blob/main/docs/install.md#下载现成的不需要装-rust)。
