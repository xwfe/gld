## 从 v0.8.1 升上来

换二进制、`gld daemon restart`。Client ID、授权口令、签名密钥、ChatGPT 注册的客户端都不动，连接器不用删、
不用重新授权。

- **ChatGPT 要点一次 Refresh**：工具表多了 `list_project_commands`（29 → 30 个），`read_output`、`change_summary`
  的参数和 `exec_command` 的说明也改了。到 chatgpt.com/plugins 打开 gld 这条连接点 **Refresh**，再开新对话；
  不点照常能用，只是 AI 看不到新工具和新参数。
- **守护进程协议号没变（还是 5）**，但版本号变了：换完没重启时命令行报"守护进程版本不一致"（退出码 4），重启就好。

完整步骤、升级前后怎么比工具表指纹见[安装 · 升级](https://github.com/xwfe/gld/blob/main/docs/install.md#升级)。

## 这一版（0.8.2）的变化

- **不用先翻文档猜项目怎么构建、怎么测：`list_project_commands`**。只读列出 `Cargo.toml` / `package.json` 里写好的
  命令（每条带能原样交给 `exec_command` 的 `argv` 和 `workdir`、按名字猜的用途、会不会被放行）、该用哪个包管理器、
  依赖装没装，以及 `.github/workflows` 里 CI 实际跑的 `run:` 步骤（`ci_steps`）。什么都不跑、不装。
  见[概念 · 项目怎么构建、怎么测](https://github.com/xwfe/gld/blob/main/docs/concepts.md#项目怎么构建怎么测list_project_commands)。
- **装依赖要你点头**：npm / pnpm / yarn / bun 的 `install`、`i`、`add`、`ci`，以及依赖没装时会顺手先装依赖的
  `pnpm run …` 这类命令，`exec_command` 不带 `confirm=true` 不跑。ChatGPT 实测：以前它把"按 CI 全跑一遍"当成
  同意、没问就装了依赖；现在会先问你，你同意了它才带 `confirm=true` 装。`pip install`、`cargo build` 拉依赖不拦。
- **跑命令的回包多一句人话 `command_summary`**：失败的以 `command FAILED` 开头，根本没起来的（找不到程序、
  脚本没可执行位）以 `command was NOT started` 开头并写明原因。以前退出码 101 时顶层仍是 `ok: true`，AI 容易看成成功。
- **几处 AI 实际撞上的不顺**：
  - `read_output` 也收 `session_id`（`exec_command` 回的就是它），以前要换成 `output_ref` 才读得到。
  - `task_manage` 每个动作只收自己的参数，传错了报 `INVALID_ARGUMENT` 并指出该用哪个动作；以前悄悄忽略，
    `finish` 带的 `summary` 也没记下，现在记成任务事件。
  - 任务指纹不再统计 Playwright 默认输出的 `test-results/`、`playwright-report/`、`blob-report/`，后台跑完 E2E
    不会让下一次 `apply_patch` 报 `FILE_CHANGED_EXTERNALLY`。
  - `change_summary` 的事件只回精简版（以前一次 `finish` 能回 43 KB），完整的走 `task_manage action=events`。
  - `exec_command` 的说明写明 10 分钟上限会停掉后台的 dev server，并给出让测试框架自己起服务的做法。
  - 默认命令白名单加了 `rustc`：接手 Rust 项目时 `rustc --version` 不再被拒。
  - Unix 上项目里带可执行位的脚本（比如 `scripts/build.sh`）直接能跑，以前扩展名不在名单里就被拒；
    没可执行位的仍被拒，但会说明用解释器跑或请你 `chmod +x`。
- **运行记录和历史里的口令抹得更干净**：`GITHUB_TOKEN=…` 这类带前缀的变量名、JSON 里的 `"password": "…"`、
  `--token abc` 这种空格隔开的参数、网址里的 `user:口令@`，以前会原样进运行记录（`list_runs` 回的命令原文）、
  任务 summary 和历史检查点。命令的输出本身仍不脱敏。

## 可能影响你的行为变化

- 脚本或自动化经 `exec_command` 装依赖的，要加 `confirm=true`，否则报 `DANGEROUS_OPERATION_REQUIRES_CONFIRMATION`。
- `exec_command` 起的项目命令拿不到 gld 的 `GLD_HOME`：项目命令不该知道 gld 的凭据放在哪。
- `change_summary` 去掉了从没起过作用的 `change_id` 参数；`read_output` 的 `output_ref` 自带的流和 `stream` 冲突时报错，
  以前悄悄按 `output_ref` 读。
- 工具数：compact 30、core 42、advanced 56、read-only 23（各多一个 `list_project_commands`）。

## 退回 0.8.1

换回旧二进制、`gld daemon restart` 即可，数据目录不用动。退回后 ChatGPT 若已刷新过工具表，再点一次 Refresh。

## 下载校验

每个包旁边有 `SHA256SUMS`：

```bash
shasum -a 256 -c SHA256SUMS      # Linux 上是 sha256sum -c SHA256SUMS
```

核对包是这个仓库的发布流水线编的（要装 GitHub CLI）：

```bash
gh attestation verify gld-v0.8.2-aarch64-apple-darwin.tar.gz --repo xwfe/gld \
  --signer-workflow xwfe/gld/.github/workflows/release.yml
```

macOS 和 Windows 的包没有代码签名，第一次运行会被 Gatekeeper / SmartScreen 拦，处理办法见
[安装](https://github.com/xwfe/gld/blob/main/docs/install.md#下载现成的不需要装-rust)。
