## 从 v0.9.0 升上来

换二进制、`gld daemon restart`，步骤见[安装 · 升级](https://github.com/xwfe/gld/blob/main/docs/install.md#升级)。

- **ChatGPT 连接器什么都不用做**：工具表没变，不用 Refresh，不用重新授权。
- **守护进程协议还是 16**。
- 有命令在跑时 `gld daemon restart` 不重启、先列出来，确定要停加 `--force`。

## 这一版的变化

这一版只动原生节点（实验），让新机器一条命令接进 Hub。用法见[接入一台新机器](https://github.com/xwfe/gld/blob/main/docs/concepts.md#接入一台新机器)。

- **一条命令安装**：Release 附带 `install.sh`、`install.ps1`，核对校验和、试跑后才替换旧版。
- **`gld node invite` 直接给命令**：打印 macOS、Linux、Windows 要跑的安装和加入命令，版本和 Hub 一致。
- **`gld join` 少写参数**：`--share` 能写目录，配置默认放数据目录，`--autostart` 接入时顺手开自启动。
- **`gld node autostart`**：launchd、systemd 用户单元、Windows 登录计划任务，崩溃后 10 秒拉回。
- **`gld node doctor`**：在目标机上握手一次，每项失败给修法。
- **代理**：配对和长连接都认 `HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY`，只支持 HTTP CONNECT。
- **修复**：Hub 读不了节点数据时回 503，不再回 401 让节点以为被撤销。

macOS 的 launchd 和 Linux 的 systemd 真机跑过。Windows 计划任务没跑过，`install.ps1` 只在 CI 上跑过。

## 可能影响你的行为变化

- `gld node invite` 默认用固定入口。没有固定入口，或入口是临时 Cloudflare 地址、OpenAI 隧道时直接拒绝，用 `--hub` 指定地址。
- 环境里设了 SOCKS 或 HTTPS 代理时，节点启动就报错，不再忽略它直连。不走代理的 Hub 写进 `NO_PROXY`。

## 退回 0.9.0

开过自启动的目标机，先用新版跑 `gld node autostart disable`：0.9.0 不认自启动定义里的 `--service`，不撤就会反复启动失败。然后换回旧二进制，`gld daemon restart`；0.9.0 的 `gld node run` 要写 `--config`。

## 下载校验

每个包旁边有 `SHA256SUMS`：

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS    # Linux 上是 sha256sum -c --ignore-missing SHA256SUMS；只核你下了的包
```

核对包是这个仓库的发布流水线编的（要装 GitHub CLI）：

```bash
gh attestation verify gld-v0.10.0-aarch64-apple-darwin.tar.gz --repo xwfe/gld \
  --signer-workflow xwfe/gld/.github/workflows/release.yml
```

macOS 和 Windows 的包没有代码签名，第一次运行会被 Gatekeeper / SmartScreen 拦，处理办法见[安装](https://github.com/xwfe/gld/blob/main/docs/install.md#下载现成的不需要装-rust)。
