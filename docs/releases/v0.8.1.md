## 从 v0.8.0 升上来

换二进制、`gld daemon restart`。Client ID、授权口令、签名密钥、ChatGPT 注册的客户端都不动，连接器不用删、
不用重新授权。

- **ChatGPT 要点一次 Refresh**：工具表多了 `list_runs`（28 → 29 个）。到 chatgpt.com/plugins 打开 gld 这条连接
  点 **Refresh**，再开新对话；不点照常能用，只是 AI 看不到新工具。
- **守护进程协议号没变（还是 5）**，但版本号变了：换完没重启时命令行报"守护进程版本不一致"（退出码 4），重启就好。

完整步骤、升级前后怎么比工具表指纹见[安装 · 升级](https://github.com/xwfe/gld/blob/main/docs/install.md#升级)。

## 这一版（0.8.1）的变化

- **不知道 `session_id` 也能找回自己的命令：`list_runs`**。换了对话、gld 重启过，都能列出这个客户端在这个项目里
  起过的命令（新的在前，带终态、退出码、时间、每个流写了多少字节），拿 `output_refs` 交给 `read_output` 读输出。
  只列自己的，别的客户端起的不列也不计数；只读，不停命令、不重跑。命令行用 `gld tool call list_runs`。
  见[概念 · 命令的输出能读多久](https://github.com/xwfe/gld/blob/main/docs/concepts.md#命令的输出能读多久stdin-怎么关)。
- **GPT Actions 修了两处**：
  - 在 Actions 上调 `exec_command` 以前必然失败（服务端崩掉、连接被掐断，GPT 那边什么也收不到），现在正常。
  - Actions 以前和本机 `gld tool call` 共用一个身份，两边读得到对方的命令输出；现在是各自的主体。
- **Windows 上第一次真正跑起来**，修了两个只在 Windows 上出现的问题：
  - gld 主线程栈只有 1 MiB，debug 构建的 `gld add` 直接栈溢出；现在和 macOS / Linux 一样 8 MiB。
  - 后台守护进程会继承调用方的输出管道，脚本里 `$(gld ls)` 这类捕获输出的调用在自动拉起守护进程时一直卡住。
  CI 的 Windows job 现在逐条跑守护进程起停、命名管道、单实例锁、命令终态和运行记录这一组端到端测试。
  这是构建产物上的测试，Windows 下载包本身还没在真机上跑过。

## 可能影响你的行为变化

- 用 GPT Actions 起的命令，本机 `gld tool call` 不再读得到它的输出，反过来也一样。
- 工具数：compact 29、core 41、advanced 55、read-only 22（各多一个 `list_runs`）。

## 退回 0.8.0

换回旧二进制、`gld daemon restart` 即可，数据目录不用动。退回后 ChatGPT 若已刷新过工具表，再点一次 Refresh。

## 下载校验

每个包旁边有 `SHA256SUMS`：

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS    # Linux 上是 sha256sum -c --ignore-missing SHA256SUMS；只核你下了的包
```

核对包是这个仓库的发布流水线编的（要装 GitHub CLI）：

```bash
gh attestation verify gld-v0.8.1-aarch64-apple-darwin.tar.gz --repo xwfe/gld \
  --signer-workflow xwfe/gld/.github/workflows/release.yml
```

macOS 和 Windows 的包没有代码签名，第一次运行会被 Gatekeeper / SmartScreen 拦，处理办法见
[安装](https://github.com/xwfe/gld/blob/main/docs/install.md#下载现成的不需要装-rust)。
