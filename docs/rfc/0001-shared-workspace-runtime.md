# RFC-0001：复用社区工作区服务，统一多产品执行接口

日期：2026-09-15。状态：评审中；本文给出推荐决策与实施门禁，不表示执行路径已迁移。

本轮交付：复核 Opus 总结、确定架构方向、固定候选版本、定义迁移与验收。未创建新仓库、安装依赖、调用模型、变更系统身份或部署服务。ccnm 的阶段状态不在本文维护。

## 1. 决策摘要

**目标是一个可由多个产品通过接口调用的工作区执行服务，不是必须自己实现一个 Rust 库。**

- **架构选择：服务复用优先。** WebCodex Server + Runner 是第一准入候选；通过公共接口使用，不先拆它的 crate、不先长期 fork。
- **候选状态：试用，不是生产采用。** 首轮固定 WebCodex `v0.4.1`，源提交 `f080c8f3ea70e37bd9f17fdd0e1b4c3a3aa330f8`。main 的新增能力不计入该版本。
- **产品保持独立。** gld 保留既有入口与产品状态；ccnm 保留官方 Agent 管理、公开协议和执行身份边界。先接 gld 的隔离试点，ccnm 后接且单独立项。
- **不自建模型循环。** 普通项目操作不调用模型；自主编程仍交给官方 Agent。WebCodex 的可选 ACP 路线不进入第一版。
- **不立即建 `workspace-kernel`。** 只有服务准入失败且有具体不可接受的缺口，才评审小范围组件复用；失败不自动授权另一套完整内核。

“维护核心项目”首先意味着维护上游版本、受控配置、薄客户端适配与契约测试，不要求拥有一套自研工具实现。将 Go 项目重写成 Rust 或复制大仓库的内部 crate，都不符合本次减少维护量的目标。

事实核查、上游与本地代码定位见[证据附录](0001-shared-workspace-runtime-evidence.md)。

## 2. 为什么修正 Opus 的结论

保留：不重复实现模型循环；两产品不合并；权限、恢复、输出与进程生命周期必须测试；社区基础库优先于手写底层机制。

修正以下推理：

| 原判断 | 本方案的修正 |
| --- | --- |
| 没有同时发布为库、带事务和写锁的项目，所以只能自己做内核 | 用户需要的是服务 API。能独立部署并提供接口的项目，同样可以整体复用；是否发布 crates.io 不是服务准入条件 |
| 两边读文件和路径规则基本一致，采用 ccnm 超集即可 | 编码、长行预算、总行数、路径和保护目录规则不同；统一实现不能偷偷改变公开行为 |
| 采用 cap-std 就没有竞态；使用进程组就能彻底清理命令 | 组件有作用范围，不代替并发版本控制、事务恢复、OS 隔离与进程逃逸测试 |
| 两产品安全前提相反，统一服务必然牺牲一方 | 不同的身份和策略可以在同一接口体系下隔离部署；不能把“统一 API”实现为“全部用同一个账号执行” |
| ccnm Remote MCP 要等真机验收后才能研究接入 | 当前仓库记录该契约已于 2026-09-11 冻结；新网关/后端链仍须重新验证，旧证据不能替新链背书 |
| 立即建立共享仓库、升级 gld 到 Rust 1.89 | 服务调用不要求调用方和执行端使用同一 Rust 版本；先保持锁文件与工具链，不因提案升级 |

## 3. 选型与不选项

本次权重：现成功能/API 覆盖 40%，维护与版本稳定性 25%，安全及故障恢复 25%，迁移与退出成本 10%。没有运行基准，不编造性能分或加权总分；硬性隔离门禁不能被其他优点抵消。

| 方案 | 覆盖 40% | 维护 25% | 安全/恢复 25% | 迁移 10% | 决策 |
| --- | --- | --- | --- | --- | --- |
| 两产品各自维护（基准） | 已有业务能力 | 基础逻辑重复 | 边界不同，存在已识别缺口 | 当下最低 | 保留为过渡路径，不作为长期目标 |
| WebCodex 整体服务 | 原生工具、Runner、Job、MCP/REST 已存在 | 0.x，须锁定版本；未见长期 API 兼容承诺 | 必须完成本方案准入 | 主要是客户端适配与部署 | **第一试用候选** |
| MCPX / Fylane | 工作区工具服务形态匹配 | Go，且均较早期 | 已有明确限制或待解决问题 | 可接口接入，不必翻译成 Rust | 对照/参考，不并行维护三个后端 |
| Codex / Goose 完整 Agent | 擅长自主任务，不等于受限多项目工具服务 | 复用官方服务接口优于内部 crate | 原生工具、直接控制 API、外部执行器边界不同 | 接入会话仍需产品适配 | 作为可选自主任务引擎，不替代所有确定性工具 |
| 自建 `workspace-kernel` | 仍需自己组装服务和协议 | 新增长期公共库维护 | 仍需自己证明恢复、权限、锁 | 两产品均须侵入修改 | 当前不选，必要时仅提取已证明重复的小组件 |

## 4. 目标架构和状态归属

```text
gld / ccnm / 未来 Web、桌面、CLI 产品
                │
         薄 RuntimeClient 适配
                │ 公共服务接口
        WebCodex Server（候选）
     授权、路由、执行任务与事件
                │
     按执行身份部署的 Runner
       文件 / 补丁 / Git / 命令 / 验证

自主编程：独立官方 Agent 生命周期，后续按需对接；第一版不新建模型客户端。
```

“一个核心”指一套受管实现和接口，不承诺一个进程、一个账号或高可用集群。上游已有 HTTP/MCP，不先在它前面再建一套通用 HTTP 网关。跨语言产品直接用公共协议；只有实际出现两个调用方后再抽共享客户端包。

| 状态/职责 | 权威归属 | 禁止做法 |
| --- | --- | --- |
| Goal、Plan、History、业务验收 | 原产品/独立 Orchestrator | 将上游同名 Task/Goal 自动替换现有状态 |
| workspace → backend/Runner/project ID 映射 | 操作员受控配置 | 接受模型传入任意 root、SSH host、私钥或覆盖路由 |
| project root、OS 身份、资源边界 | 执行端受控配置 | 由客户端声明自己具备高权限 |
| Job、输出游标、取消与执行终态 | 执行后端 | 把 HTTP 成功当执行成功；复制一个随时漂移的本地任务真相 |
| 官方 Agent 登录与会话 | 现有 ccnm/官方 Agent | 将登录凭据交给 Runner，或复制订阅凭据 |
| 业务“完成” | 调用产品根据证据判断 | 将 Agent 自称完成或命令退出 0 自动当作所有验收通过 |

第一版只使用显式调用，不引入自动 Planner、Router、任务图、无限 retry、worktree 自动合并、Office/浏览器自研工具链。确有新 work 能力时优先接现成工具服务，另定权限与验收。

## 5. 第一版调用契约

以下是适配层必须满足的能力清单，不是声称这些名称已成为上游 REST 路由。优先使用固定版本的 MCP `tools/list` / `tools/call` 或统一 `/api/tools/call`；不要逐个绑定旧的 `/api/projects/*` 专用路由。

| 能力 | 适配要求 | 不允许的“兼容” |
| --- | --- | --- |
| 能力发现 | 明确 backend 版本、操作集、预算、分页/取消/恢复能力；缓存与版本绑定 | 上游有同名工具就假设参数和语义相同 |
| read/list/search | 保留调用产品的 UTF-8、BOM、隐藏文件、ignore、排序、行号、字节/行预算与游标约定 | 将 lossy 解码、完整总行数变未知或默认跳过 .gitignore 当作无变化 |
| patch | 保留外部格式，明确 create-only、前置版本、重复片段、冲突、dry-run；只做已证明无损的参数转换 | 找到多个 old 文本时擅自取第一个；为了成功重试而放宽匹配 |
| exec/job | 明确 argv/命令字符串区别、cwd、环境、超时、输出截断、stdin、输出续读、取消与保留期限 | 经 shell 拼接模拟 argv；把长期 Job 静默降成阻塞短命令 |
| Git/验证 | 返回实际命令、退出状态、受限输出引用、相关版本和变更证据 | 没跑测试却写 passed；把输出被截断误作空输出 |
| 失败/恢复 | 分离拒绝、执行失败、取消完成、结果未知；标明能否对账及是否允许重试 | 断连后返回成功/失败的猜测结果；重新启动相同副作用 |

### 授权和写入权威

1. 服务端授权绑定调用者、项目、操作范围；先检查原产品限制，再受执行端策略约束，两者只能取交集。模型提供的 `confirm=true` 不是跨产品通用的人类审批凭证。
2. 每个真实项目的写入只有一个受控执行通道；从读检查到提交完成、从命令启动到子进程确认退出，写权不能出现空窗。
3. 锁的身份依据真实资源，不按可重名的显示名称。同一 Git common directory、worktree、别名路径按原有契约处理；不能因换服务而默认放开并行。
4. 共享一个 Rust 类型、一个 token 或相同路径字符串，都不证明跨进程/跨身份共享了同一把锁。上游不能满足时，不开放两个后端同时写同一工作区。
5. 保留 ccnm 的执行身份、凭据审计、Runtime root 权威和写 guard。WebCodex 项目注册、ACP cwd、文件检查不能代替 OS 隔离；第一版禁用试点不需要的 shell/ACP/上游代理能力。

### 请求和结果生命周期

- 后端选择绑定 workspace 和正在运行的任务。任务中途不得换后端；不认识的能力返回明确的不支持。
- 只有已证明安全的读取可以自动重试。patch、命令启动、Agent prompt 默认不得因超时重发。
- 每项有副作用的能力在 P0 固定为“后端同键去重”或“不允许重放”。前者必须验证真实幂等；后者禁止客户端自动重发，只能对账或返回待核对状态。原产品已经承诺幂等的接口不能降为不允许重放，不满足则不迁移该能力。仅在客户端缓存一个请求 ID 不能消除服务端已执行但回包丢失的窗口。
- 对结果未知的操作先按已有 ID、变更与后端证据对账；对不上则保留 `outcome_unknown`。不得切旧后端重做同一请求。
- 进程退出 0、验证通过、业务验收通过是三个层次；未执行/输出过期/结果缺失必须单列。

### 固定版本的已知能力边界

- `v0.4.1` 已有原生工具、Job、Runner，以及可选 ACP start/observe/cancel。
- 原 Runner 仍存活且支持 reconciliation 时，Server 重启可恢复部分原 Job；不等于 Runner 重启后能恢复同一进程。
- main 的普通终态 Job 持久回执不在 `v0.4.1`。试点分别测试“运行中任务恢复”和“已完成结果保留”；缺失能力不由适配器伪造。
- ACP 的批准后继续执行链未完整提供。第一版排除 ACP，自主 Agent 继续走现有路径。
- 若必须依赖 main 修复，先评审最小回移或另一个固定提交，独立重跑全部相关门禁；不能无声地从 release 跟到 main。

## 6. 实施阶段与停止点

阶段按依赖执行，不同时开发共享库、替换 MCP SDK、升级工具链和接入多个 Agent。下表是未来实施计划，不是本轮已完成项。

| 阶段 | 交付与边界 | 通过条件 / 停止点 |
| --- | --- | --- |
| P0 契约与发布物基线 | 保存两产品输入/结果 fixture；固定 Server/Runner 版本、平台、制品 hash、schema、配置与授权；冻结各能力的重试语义、门禁适用矩阵与量化阈值；只用临时项目和合成凭据 | 有可重建实验基线；没有预先冻结的门禁表不能进入 P1。不修改真实项目、不装系统服务；下载/安装执行物遵循项目授权边界 |
| P1 原生只读闭环 | 不改生产路径，用独立中立客户端直连候选；read/list/search/Git 查询；在同一快照的两份副本做差分 | G01–G04、G11 的只读部分通过；所有差异已解释并分类。不以更改旧 fixture 掩盖差异 |
| P2 写入与执行闭环 | 临时项目完成 patch → test/build → diff → Job 输出/取消 → 故障恢复；不启用模型 | G01–G12 中适用项全部通过；写入、恢复、授权阻断项一项未过即停止切换 |
| P3 gld 小范围试点 | 增加一个内部候选 backend 适配；默认仍为原实现；只为显式选择的试点工作区切换；公开 Tool API 不变 | gld 相关契约/安全/回归门禁全过，完成真实客户端闭环和一次回退演练，再扩大项目范围 |
| P4 第二消费者与 ccnm | 先证明独立第二客户端可调用。ccnm 按当前计划机制另立新阶段；优先通过 `ccnm mcp bridge` 公共接口复用已隔离 Runtime，不直连 internal 协议 | ccnm 冻结协议、独立 Python 黑盒客户端和新执行链的真实身份/写权测试通过。保留 ccnm 后端时只能宣称接口复用，不能宣称两套内核已完全合一 |
| P5 收敛维护面 | 对已迁移范围停止扩展旧实现；记录至少一次上游升级和回退；确认无旧客户端或活动任务依赖后再删旧代码 | 删除仅限已被验收覆盖的重复实现；有替代证据、有退出路径，不按日历自动清理 |

**P4 不意味着自动用 WebCodex 替换 ccnm 的全部 Runtime。** 若以后确实要做到一个底层执行实现，必须另证 WebCodex Runner 与 ccnm 身份/写权/恢复契约等价；否则保留隔离后端是显式取舍，不为了“统一”降低边界。

### 原实现缺口的处置

以下是独立修复队列，不夹带进等价迁移提交：gld Git 超时未生效、进程树清理保证不足、patch 重复片段定位风险、完成后输出引用保留不一致；ccnm 读长行分配与协议预算说明也需分别处理。详见证据附录。

只读试点不必等所有修复完成；实际写试点和回退目标必须先评审这些风险。不能拿已知不安全的旧路径当“保险回退”，也不能靠更换后端掩盖原缺陷。

## 7. 准入测试与证据

中立客户端只通过公开协议调用，不 import gld、ccnm 或 WebCodex 内部实现。一个测试目录对应一份独立项目副本；写操作不在同一个真实目录上双跑。已有测试保留，新的差分测试补覆盖，不能把迁移前后的差异录成新 golden 就算通过。

### P0 必须冻结的判据

每个“平台 × 能力 × 用例”记录必测/不适用及理由、不启用的能力、重复请求语义与资源预算。只有不暴露的能力才能排除相应测试；授权、项目隔离、错误真实性不能列为不适用。不能跑出失败后再改成不适用。

以下是首轮建议预算，不是已测性能；P0 用既有实现基线复核后，在候选实验前冻结。确需改变阈值时记录原因并重新评审受影响项，不通过调阈值掩盖已经发生的回归。

| 项目 | 首轮判据 |
| --- | --- |
| 普通只读调用 | 固定 fixture，10 秒客户端 deadline；非法路径/FIFO 不能无限等待。更大数据集另列预算 |
| 命令取消 | 测试命令 timeout 设为 2 秒；请求取消或超时后 5 秒内确认普通受管子孙退出、管道回收，否则失败。自行逃离进程组的用例独立列隔离能力与边界 |
| 输出预算 | 请求 32 KiB 输出内容预算；协议包装、base64 和省略标记单独计量；分页拼接不得漏字或重复字 |
| 超长单行 | 同一进程基线下测试 8 MiB 与 128 MiB 单行文件，只取有界页面；两档峰值 RSS 增量不超过 32 MiB，或按事先公开的文件大小上限在读取前拒绝。拒绝是否兼容仍按产品契约判定 |
| 性能比较 | 相同平台、拓扑、数据和预算，预热后至少 20 次；只读 p95 不超过旧实现的 1.5 倍加 50 ms。旧实现本身失败的用例使用预先定义的绝对预算，不比较错误结果的速度 |
| 重复/中断 | 每条选定路径至少重复 20 次；写入前、已写未回包、回包后分别注入故障；零越权写、零被隐藏的错误片段写入、零违反已声明重试语义的重复副作用 |

这些判据只覆盖首轮试点，不据此声称任意规模仓库、任意硬件或任意网络都有相同性能。

| 编号 | 必测场景 | 可判定的验收结果 |
| --- | --- | --- |
| G01 API/配置 | 版本不匹配、未知工具/字段、权限不足、预算非法、能力缺失 | 无副作用；错误明确；未知能力不静默降级。冻结协议兼容或单独记录被批准的行为变化 |
| G02 项目隔离 | 非授权项目、绝对/父路径、symlink 切换、保护目录、合成私有文件 | 按原产品策略拒绝；敏感内容不进入返回/日志；Runner root 不能被工具参数覆盖 |
| G03 有界读取 | UTF-8 边界、BOM、非法字节、二进制、FIFO、空文件、超长单行、多页读取 | 不挂死、不漏字/重复字；内存有界。以固定块大文件测试核对，不只检查返回字符串长度 |
| G04 搜索兼容 | .gitignore、隐藏文件、symlink、正则/字面量、CRLF、Unicode、排序、结果上限 | 有版本化的语义差分；不自动启用 ignore 改变既有搜索范围 |
| G05 patch 正确性 | 重复 old 片段、多个 hunk、create-only、过期版本、删除/移动、dry-run | 定位正确或明确冲突；预检不写盘；拒绝歧义，不修改错误片段 |
| G06 提交恢复 | 第 N 个文件失败、磁盘/权限错误、rename 前后中断、恢复再次中断、可执行位、Windows 替换 | 不伪报成功；保留可核对的已写/未写状态；不静默覆盖期间用户修改。单文件 rename 原子性不冒充多文件崩溃原子性 |
| G07 资源互斥 | 两客户端、别名路径、同仓库多 worktree、存活/崩溃 writer | 无并行越权写；保持原锁范围；不按超时直接夺取不确定写权 |
| G08 重试/重连 | 请求已发未回、相同请求重复、Server 重启、Runner 重启、最终输出丢失 | 声明同键去重的操作验证重复请求仅执行一次；声明不允许重放的操作验证客户端不重发、不切后端补执行，按 ID 对账或结果未知。原产品幂等承诺不能降级；终态回执与运行中 Job 恢复分别记录 |
| G09 进程生命周期 | inline/yield 超时、显式取消、持有输出管道的子孙进程、stdin EOF、自然结束、排队取消 | 确认受管进程退出后才报告取消完成/释放写权；无孤儿读管道。逃离进程组的能力边界单列，不作无限制清理保证 |
| G10 输出与验证 | 快速超量输出、尾部非零退出、UTF-8 截断、完成后续读、过期引用 | 输出可按契约续读或明确过期；stdout/stderr/退出码不混淆；传输成功不冒充验证成功 |
| G11 平台/凭据 | macOS、Windows gld 目标；ccnm 已支持的 Runtime 平台；环境继承和日志 | OS 隔离与凭据边界不弱化；无不必要继承；平台未实测就不启用相应写后端，不把交叉编译当运行证明 |
| G12 切换/回退 | 有活动 Job、未决写入、未解决审批、旧输出引用、数据 schema 升级 | 先排空或确认取消，再切换；未知执行先处理；旧结果保留可追踪；不重放有副作用的操作 |

每个结果保留：用例 ID、输入 fixture hash、产品/后端完整版本、OS/文件系统与执行身份、脱敏配置、原始请求/响应、退出状态、相关文件前后 hash、残留进程检查、执行时间和限制。仅 fixture 中使用假凭据；不采集个人认证内容或完整环境。

性能不凭 Rust 或下载量推断。P0 记录代表性小/大仓库的延迟、内存峰值、输出大小；P2 以相同数据按冻结阈值重测。越界即暂停该能力迁移，不通过改变检索范围或截断更多输出来“优化”。

## 8. 回退、退出与供应链

### 回退流程

1. 停止接收该工作区的新写请求；列出并排空受管 Job。
2. 有 `outcome_unknown`、未决事务或残留进程时先对账，不直接改回旧后端。
3. 保存后端数据、任务/输出引用、审计与当前项目状态；数据库只使用经过验证的备份/快照方式。
4. 在没有活动写者且旧路径已通过安全回归后切回原后端；只做配置切换，不执行 reset/clean，不覆盖用户修改。
5. 文件内容的恢复是另一项受控操作：核对预期版本与影响范围后再恢复。后端回退本身不等于撤销业务写入。

升级前记录数据库 schema 与向后兼容性；无法读取新 schema 的旧二进制不得直接启动。备份用于恢复服务状态，不作为重放命令的指令。

### 放弃本候选的硬条件

- 必须扩大项目目录/凭据可访问范围或绕过 ccnm 写权才能工作。
- 关键重复执行、事务不确定性、进程清理或平台门禁不能满足。
- 适配层不得不再实现文件写入器、完整 Job 状态机、权限引擎或整套模型循环。
- 每次上游升级都需大量私有 patch，或公开接口缺口无法通过可维护方式解决。

命中后停止受影响范围，保留原后端并写明证据；重新选择服务或评审一个有边界的小组件补丁，不自动扩大自研范围。

### 版本与依赖策略

- 先使用匹配平台、同版本的 Server/Runner，记录来源与制品 hash；有签名时验证签名。hash 只证明文件一致，不等同可信来源或安全审计。
- 首轮不增加 cap-std/process-wrap/ignore/rmcp 等依赖，不复制 Codex 代码、不升级两个项目的 MSRV。API 复用与这些库的选型分开。
- 若后续必须修改基础实现，先用真实用例验证库的行为与目标 MSRV，再锁定版本/features；保留已有 Cargo.lock，不因“最新版”升级。
- Go 的 `internal/` 限制进程内导入，不限制调用已部署服务。Apache/MIT 等代码复用须保留适用版权、许可和第三方通知；不把“保留 NOTICE”理解为可忽略其余义务。

## 9. 本轮状态与下一实施入口

- 本轮完成的是推荐方案和证据核验；P0–P5 产品实施、G01–G12 准入均未执行。
- 未改 gld 的 Tool API、ccnm 的任何文件/阶段、依赖、工具链、系统身份或已安装服务。

- ccnm 当前 P0–P12 已结束、`current_task=null`；涉及它的产品改动须按其 `docs/plan/` 新设阶段，不在本 RFC 标记该产品已迁移。
- 正式替换已安装程序、创建账号/ACL/防火墙、公开网络入口、模型付费调用和外部发布均不由这份方案自动授权。
