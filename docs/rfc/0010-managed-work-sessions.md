# RFC-0010：无需用户建项目的通用任务空间

起草日期：2026-10-26。本文保留整体设计与分期，当前排期、代码及部署进度只看 [task_plan.md](../../task_plan.md)。
已经实现部分的实际工具规则以 [concepts.md](../concepts.md#不属于项目的任务work_session) 为准；
后续 W1/W2 的产物保留、收尾与回收契约仍是计划，不能将本文所有动作视为当前可调用接口。

## 1. 用户体验与范围

用户提出“打开应用、下载并转换文件、整理指定资料、操作网页或桌面”时，gld 自动提供执行目录。
用户不需要新建 Git 仓库、运行 `gld add`、给临时项目命名或另外配置连接器。

已有项目任务仍显式选择其 workspace。通用任务由 gld 创建内部执行上下文，后续复用现有文件、
命令和运行记录工具；缺少 workspace 的原有调用继续拒绝，不增加可变的全局“当前项目”。

本方案承载目录、资源归属和收尾，不新增一套 Goal/Plan/Task 调度系统。业务任务需要长期追踪时，
关联现有 Harness；关闭资源会话不等于业务验收通过。桌面控制见 [RFC-0011](0011-computer-use.md)。

起草时只授权制定并保存方案。后续编码按用户要求分段实施；安装 provider、更改现网权限、
换装或重启服务仍按各自操作授权执行，代码完成不代表已经部署。

## 2. 已有基础与需要接入的地方

以下根据 2026-10-26 读取的仓库源码；工作树基线为 `f6f3e02`，不是新功能验证结果。

| 已有实现 | 可以复用 | 不能直接推导的结论 |
| --- | --- | --- |
| `tools/workspace.rs::Workspace::new` | 存在的目录即可建立 Workspace，不要求 Git | 内部目录还未自动创建、登记和回收 |
| `is_gld_data_home_path` | 当前 Workspace 自身内容属于例外；其他 gld 数据仍受检查 | 不应把整棵 GLD_HOME 或用户主目录作为通用根 |
| `hub/mod.rs` 的显式 workspace 路由 | 现有工具继续传 workspace 标识 | 不允许遗漏参数时落到某个隐式目录 |
| `tools/workspace_runtime.rs` | 目录级写锁、按调用方区分的命令会话 | OAuth client_id 不是聊天 ID，目录也不是 OS 沙箱 |
| `tools/runs.rs` | 有界运行记录、终态和输出引用 | 记录过期不清理命令创建的业务文件 |
| `machine_mcp/` | 连接、调用、媒体回包和进程收尾 | provider 的 cwd、缓存和浏览器 profile 不会自动跟任务走 |
| `app/prune.rs` | 扫描、确认清单、删除前复核 | 当前只认登记项目，必须接入托管空间的存活集合 |

不重做已经实施的 [RFC-0006](0006-machine-mcp.md)，也不调整现有客户端身份、服务地址和 OAuth 注册。

## 3. 目录与元数据

所有位置由实际 `GLD_HOME` 解析，不硬编码用户家目录。

| 位置 | 内容 | 谁能直接修改 |
| --- | --- | --- |
| `GLD_HOME/work/<id>/` | 输入副本、临时脚本、截图、下载和处理中间物 | 对应 workspace 的文件工具和获准运行的程序 |
| `GLD_HOME/artifacts/<id>/` | 用户选择保留的最终文件 | gld 负责落盘和归属检查；通过产物接口访问 |
| `GLD_HOME/managed-workspaces/<id>.json` | root、owner、保留策略和资源引用 | 服务内部；不放进可编辑的任务根 |
| 现有 `runs/`、`harness/`、`agents/` | 继续承担各自已有记录 | 继续走原有接口 |

元数据只保存资源事实：随机 ID、schema_version、canonical root、创建者、创建/最后活动时间、
生命周期、保留期限、产物引用、关联的现有 task_id，以及正在使用它的命令/provider/桌面会话引用。
不存第二份业务目标、步骤队列或审批结果。

每次创建得到独立目录。返回不透明的 workspace ID；展示名不能覆盖用户现有项目名称。
业务项目列表继续以项目为主，通过简短能力提示引导通用入口；托管空间由通用入口列出，不冒充用户仓库。

路径规则复用 canonicalize、相对路径和符号链接检查。清理前同时检查登记归属与真实路径；
不扫描并删除“看起来像临时文件”的任意目录。未知目录保留并报告，服务配置、凭据和其他任务不进入删除清单。

## 4. 最小公开入口

拟新增一个聚合工具 `work_session`，复用当前 hub，不另起服务：

| action | 最少输入 | 返回与语义 |
| --- | --- | --- |
| `start` | `client_request_id`；可选简短用途 | 创建或返回同主体同请求的 workspace，返回路径说明、策略和资源 ID |
| `list` | 可选游标 | 只列调用方可见的托管空间，包含保留状态和空间占用 |
| `status` | `workspace` | 活跃资源、产物、剩余保留期、清理阻塞原因 |
| `finish` | `workspace`、明确的 `keep_paths` | 先保存产物，再关闭空闲资源空间；有活动资源则拒绝并列明 |
| `artifact` | `artifact_id` | 归属校验后的文件信息；文本/图像使用有界内容返回 |
| `retain` | `workspace` 或 `artifact_id`、保留要求 | 显式保留；不能借此改 owner 或越界访问 |

这些 action 是资源生命周期，不替代现有 `task_manage` 的业务验收。
`finish` 不需要为“打开应用”伪造代码测试，但必须报告保存、关闭与清理各自是否成功。

创建完成后，原有调用保持如下形状：

```text
exec_command(workspace=<returned_id>, argv=[...])
read_file(workspace=<returned_id>, path=<relative_path>)
apply_patch(workspace=<returned_id>, patch=...)
```

重试 `start` 用调用方加 client_request_id 去重。重试 `finish` 返回已完成步骤和剩余步骤，
不重复移动文件或覆盖已保留产物。过期 ID 给出明确状态，不复用为另一项任务。

第一版不建设公网下载站。二进制产物返回归属、文件名、MIME、大小、校验值和实际保存位置；
需要交付到外部目录或服务时，沿用明确指定的目标与现有获准传输能力，不因通用目录而扩大写权限。

## 5. 身份、策略与并发

- owner 使用已鉴权的调用主体，复用 `AuthContext`；同一凭据可以对应多个聊天，各自取得不同 workspace ID。
  这是任务分流，不宣称同一操作系统账号或同一凭据内有强安全隔离。
- 首版通用空间仅向已鉴权的完整服务主体开放，并受通用能力开关控制；noauth 和现有受限 grant 不自动获得它。
  后续确需 grant 支持时新增明确范围，默认关闭，不把“可写某个项目”扩大为“可操作整台机器”。
- 默认读限制和 guarded 命令策略继续生效。通用任务不继承一个随意挑选的业务仓库规则，
  加载明确的全局说明与通用任务说明，委派保持显式开启。
- 原有项目工具及 computer 观察/动作调用均显式携带 workspace；会话必须同时匹配调用方与 workspace。
  内核写锁、运行记录、provider 和桌面会话都要能追溯到该空间。
- UI 上的任务内容、网页文本和文件正文不能改变控制策略；资源元数据由服务持有。
- 命令仍不是 OS 沙箱。若需求是约束任意程序只能访问任务目录，使用独立账号/容器/VM 等单独方案，
  不把 cwd 或 guarded 文本检查宣传成该能力。

## 6. 产物与清理契约

### 6.1 保存先于删除

`keep_paths` 只能选择该任务根内、经验证的路径。对最终产物先复制或移动到保留区，
核对大小/校验值并原子提交元数据，再清理原临时文件。跨文件系统复制失败时保留源文件，
报告哪一步失败；不因接口返回超时就再次覆盖目标。

产物查询在临时目录关闭后仍然可用。保留产物不会因普通临时空间 TTL 被删除。
显式要求“只返回结果、不保留过程”时清理过程文件；要求保留过程时列出目录和理由。

### 6.2 建议的首版保留规则

| 内容或状态 | 默认策略建议 |
| --- | --- |
| 已成功交付的临时目录 | 无活动资源后即时回收 |
| 失败且已停止的临时目录 | 保留 24 小时，允许延长 |
| 中断、无人继续的临时目录 | 7 天无活动且无活资源后回收 |
| 用户明确保留的最终产物 | 不走上述 TTL；删除须有对应请求 |
| 操作摘要 | 复用原有记录；仅留产物去向、清理结果等必要信息 |
| provider 自己的缓存 | 优先配置到本任务目录；无法定向时报告实际位置，不宣称已全收 |

24 小时和 7 天是本方案建议值，不是当前软件已有配置。空间数量和字节配额可配置；
达到上限只回收确认到期的临时内容，仍不足则拒绝新增长并提示处理，不能删除活跃资源或保留产物来腾空间。

### 6.3 清理触发与并发

在创建/关闭托管空间、服务启动和显式清理时做有界扫描。没有后续触发时不承诺准点回收，
如日用证据表明空闲残留不可接受，再加服务内轻量定时扫描，不引入独立调度平台。

删除依据为服务登记、保留策略和资源实际状态，不能只看目录 mtime 或最后一次聊天调用时间。
活跃命令、未结束委派、browser profile 或有效 computer session 都阻止清理。
关闭与清理取得相同资源锁；确认后重新检查，新增资源或恢复使用的目录退出本轮清单。

服务异常退出后先标为待核对；不靠 PID 猜测归属、不自动重跑副作用命令、不删除仍被实际进程使用的目录。
清理失败保留可重试记录，不将“业务任务完成”写成“磁盘清理成功”。

## 7. 实施切片与验收

排期只在 task_plan；下表定义边界和完成标准，不保存第二份进度。

| 切片 | 改动范围 | 必须通过 |
| --- | --- | --- |
| D10-W0 | `managed_workspaces` 小模块、hub 路由/可见性、context 构建、start/status/list；纳入 hub 完整存活集合与 prune 有主记录集合 | 零用户项目也能创建；同请求幂等；两个任务文件互不覆盖；越界/错误 owner 被拒；普通工具缺 workspace 仍拒；无需 Git；后续调用不误停命令，prune 不把托管资源判为孤儿 |
| D10-W1 | finish/artifact/retain、活资源核对、到期删除和关闭重试 | 保存后读回一致；失败不删唯一源；活跃目录和日志不被误清；服务重启后可查询；过期回收只触及登记目录；关闭可重试 |
| D10-W2 | provider 文件归属与日用验收 | 下载、截图、profile 到任务目录；最终文件关闭后仍可取；不留下本任务启动的空闲子进程；产物/临时内容/外部缓存分别报告 |

优先复用的代码入口：`tools/workspace.rs`、`tools/context.rs`、`tools/workspace_runtime.rs`、
`tools/runs.rs`、`hub/mod.rs`、`app/prune.rs` 和现有 Harness 存储原语。
新增模块只管托管空间生命周期；通用 MCP 协议继续由 `machine_mcp/` 与 `toexec-mcp` 承担。

**以下两项属于 W0 的前置检查，必须在开放执行工具前完成；W1 再增加到期删除：**

1. `Hub::forget_departed` 看的是完整存活成员集合。托管空间也要在其中，再按调用方过滤可见项；
   不能临时构造 context 后，下次调用把它的后台命令误停。
2. prune 保留集合包含普通项目与仍活跃/保留的托管空间 ID 和路径哈希。
   不能因为不在用户项目列表，就把其 harness、日志或运行记录判为无主。
